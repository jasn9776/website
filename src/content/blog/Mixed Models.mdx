## Context

Mixed effects models are a type of model that extends the traditional linear regression (or logistic regression) models. Linear regression (and its logistic regression counterpart) assume that all observations are independent.
However, this is not always the case: you may be measuring the same patient over more than one timepoint and you need to account for the patient-specific effect, or perhaps you suspect that results from the same site or hospital may be more similar (correlated). They work by separating effects into fixed and random.
Fixed effects (similar to linear/logistic regression variables) are typically things we want to measure directly — for example, the effect of the treatment (or lack thereof), age, sex, smoking status,
and other relevant factors. ***Random effects are designed for the structured variation that you want to account for but generalise beyond (individual patients, hospital sites).
In order to use random effects, we need to have repeated measures for each unit (e.g. subject/hospital). These would commonly be the same patient measured across at least 2 timepoints, or each hospital needs at least 2 patients if you want a random effect per hospital.***
For example,
there could be a patient-specific effect (a random effect) for each of the research subjects. You could also introduce a random effect for each hospital site if you
suspect the specific hospital would affect the outcome. However, if there are only a small number of hospital sites — for example, only 3 — then fixed
effects are usually better (you could also leave it out altogether if you don't think it will affect the outcome in a systematic way). A rule of thumb is to only use random effects if there are more than 5 groups. This is because of a statistical method used
to calculate the random effect for each hospital, and this works best when there are many hospitals (or subjects/patients/etc.).
***A very common use case for mixed models is correlated data (such as when subjects are measured repeatedly over time).
This is a more flexible alternative to repeated measures ANOVA.***



## How to choose between fixed and random effects

Fixed effects are similar to variables in linear or logistic regression.
Random effects are what mixed models add and they allow you to account for the correlation structure of your data. ***However, random effects require multiple measurements per subject. So if you have only one measurement per patient, you will be unable to generate a random effect per patient, but you might still be able to generate a random effect per hospital, provided each hospital has at least 2 patients.***
They allow you to define an effect for something that you want to control for but do not necessarily want to measure specifically. For example,
patient-specific effects, or a patient trajectory of change (slope over time — maybe some patients just recover more quickly over time, for example).
You could also have a random effect for hospital site (to control for the fact that each hospital may have different levels of care or measurement biases).
However, as mentioned, random effects usually require at least around 5 of each group to be effective.
So if you only have 3 hospitals, it may be better to treat it as a fixed effect (as a categorical variable).
Or if you think that you have already controlled it well, you may even choose to leave it out.
(Again, please consult a suitably qualified statistician if unsure.)


# How to specify the model in R

Once you have chosen the correct structure for your model, it is time to specify it in R. Common packages include lme4 and lmerTest. Most R statistics packages use very similar syntax.

Here's some notation you should know:

A * B is a shortcut that automatically creates the main effects of A and B, plus their interaction (A + B + A:B).

A:B (for example time:group) (where time is a continuous variable — say we have 30 time points and group may be control vs treatment). ***Measures the interaction between time and group. Usually if we include the interaction effect, we should also include the main effects. So it is rarely used by itself.***

(1| subject) - here subject could also be called patient or whatever you named it — but basically it says for everything on the right-hand side (in this case for each subject),
we want a 1 (an intercept), so essentially it translates to: for each subject we want a random intercept (a random effect for each subject).

(1 + time | subject) - For each subject, we want both a constant (1) and a slope for time — so essentially we want both a random intercept and a random slope based on time for each patient: a trajectory of change, if you like to think of it that way.

Age + Sex + BMI - Age, Sex and BMI will be fixed effects.

# Examples

### Scenario A

I have 40 subjects — 20 control and 20 treatment. I am measuring IFN-γ levels. We hypothesise that the treatment will increase patients' IFN-γ levels. We measured at 5-week intervals, ending at week 30.
Since measurements from each subject will be correlated, we will need to introduce a random effect per subject. We also suspect each subject will have their own trajectory of change (so we want a random slope/trajectory based on time).
We have also measured age, sex, bodyweight (or BMI), and cholesterol levels, as we believe these are clinically relevant variables we want to control for.

We take the log of the IFN-γ variable, as is often the norm in medical contexts. After log-transforming, the variable looks approximately normally distributed. If it already looked normally distributed, we would not transform it.
(This is another area a specialised statistician can help you with.)

So the formula would go something like this:

log_infg ~ treatment*time + Age + Sex + BMI + Cholesterol + (1 + time | patient_id), if we want a random slope/trajectory for each patient/subject.

The choice depends on whether we think the model can reliably estimate a random slope/trajectory for each patient. For example, if there are only 3 time points,
it may be unstable. Again, this may be a reason to consult with a statistician, as although I can fit the model to your specifications, I do not have the depth of knowledge or experience
to determine which model is most effective in every scenario. I can try to compare models using a likelihood ratio test to see if we have enough data,
however, I cannot guarantee my judgement will align with that of an experienced biostatistician.
Random slopes for time are theoretically desirable but often overfit small clinical datasets and fail to converge (especially with too few time points).

For example, if we only had 3 timepoints, we would write it in R as:

log_infg ~ treatment*time + Age + Sex + BMI + Cholesterol + (1 | patient_id) instead (leaving out the random slope for each patient).

treatment - a categorical variable: either control or treatment\
time - a series of integers e.g. 0,5,10,15,20,25,30 if we think there is a continuous relationship, or categorical e.g.
"Baseline", "Week_4", "Week_12" if we don't think there is a continuous relationship over time.\
Age - a continuous variable\
Sex - a categorical variable: "Male" / "Female" / "Intersex" (if applicable)\
Cholesterol - a continuous variable e.g. 0–50\
patient_id - a unique identifier per patient

treatment*time means we want the main effect and the interaction effect between treatment and time. Equivalent to `treatment + time + treatment:time`.

### Scenario B:

Let's say we have 6 mice (3 control and 3 treatment). We have measured their tumour size and body weight at 30 days. We want to know if the treatment affects the
tumour size.

Since we only have one measurement per mouse, we cannot use a mixed model, so we just use a normal linear regression:

tumour_size ~ treatment + body_weight

Time is not in the formula because we only have one timepoint.

If we had multiple time measurements it might look like this:

tumour_size ~ treatment*time + body_weight + (1|mouse_id)

where time is 0, 5, 10, 15, 20, 25, 30 for example, or "time_1", "time_2", "time_3" for categorical if we don't think there is a trend\
(1|mouse_id) - Controls for individual variation within each mouse.

Whether to use (1|mouse_id) or (1+time|mouse_id) could be decided by consulting a statistician or running a log-likelihood test for both models.

## How to use emmeans

Emmeans is used when we want contrasts that are not available in the original model formula. This is often much better than what PRISM will do.

For example, ***let's say we are specifically interested in the effect of treatment at week 30 (timepoint 7).*** For the sake of example, let's say we coded time as 0,5,10,15,20,25,30 as a continuous variable.

```r
# 1. Fit the model
model <- lmer(log_ifng ~ treatment * time + Age + Sex + BMI +
                (1 + time | patient_id), data = df)

# 2. Get estimated means at each week
emm <- emmeans(model, ~ treatment | time,
               at = list(time = c(0,5,10,15,20,25,30)))

# 3. Treatment contrast at each week
pairs(emm, reverse = TRUE, adjust = "tukey")

# 4. Primary endpoint — treatment effect at Week 30
emm_week30 <- emmeans(model, ~ treatment, at = list(time = c(30)))
pairs(emm_week30, reverse = TRUE, adjust = "none")

# 5. Back-transform for reporting
summary(pairs(emm_week30, reverse = TRUE), type = "response")

# 6. Plot trajectories
emmip(model, treatment ~ time,
      at = list(time = seq(0, 30, by = 5)), CIs = TRUE)
```

### Why post-hoc adjustments are used

Post-hoc adjustments are used when we are calculating multiple p-values, in order to control for false positives. They are only needed if you care about multiple p-values. If you are only interested in one p-value (e.g. only the treatment effect at time = 30), adjustment is not needed. Doing this in R will give you more control than in PRISM over which adjustment is applied.

Common adjustments include:\
Tukey — comparing all groups against each other (every possible pair).\
Dunnett ("trt.vs.ctrl" in emmeans) — comparing several treatment groups against one control. More powerful than Tukey when this is your design, because you are making fewer comparisons.\
Bonferroni — for a small number of pre-specified comparisons that don't fit neatly into the above. Conservative but universally accepted.\
FDR / Benjamini-Hochberg (BH) — for exploratory analyses with many comparisons (e.g. screening 30 cytokines). Accepts that roughly 5% of flagged results may be spurious. Label findings as hypothesis-generating, not confirmatory.\
None — a single pre-specified primary comparison defined before data collection. Must be stated in your analysis plan in advance.\
As a general rule: the more comparisons you make, the more you need to adjust — but the harder it becomes to detect real effects. Pre-specifying your primary comparison before collecting data is the best way to reduce this tension.

### Prism vs. R
PRISM is an excellent tool for many standard analyses, but its mixed model implementation has some notable limitations.\
The post-hoc comparisons are applied automatically rather than letting you choose explicitly, and the model specification options are more constrained — meaning the results can be sensitive to how you set up your variables.\
For complex designs, this lack of transparency can be a problem. ***The mixed models in PRISM should be thought of as equivalent to a repeated measures ANOVA, along with all its limitations. In the documentation of PRISM it explicitly states that "When fitting a mixed effects model in Prism, think of it as repeated measures ANOVA that allows missing values."
See [link to documentation](https://www.graphpad.com/guides/prism/latest/statistics/stat_anova-approach-vs_-mixed-model.htm).***

R gives you full control over model specification, post-hoc adjustments, and diagnostics. The learning curve is steeper, but for longitudinal clinical data with repeated measures, it is the more appropriate tool.
That said — a poorly specified model in R is worse than a correctly applied analysis in PRISM. The tool matters less than understanding what your model is actually doing.
