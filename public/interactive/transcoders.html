Transcoders and attribution graphs

How researchers turn a language model's hidden arithmetic into a wiring diagram of concepts, built up from neurons to sparse autoencoders to the cross-layer transcoders used in Anthropic's Circuit Tracing.

No background in interpretability needed. Sections 1 to 3 assume none at all; later sections assume you know roughly what a neural network layer is.

1 · The question

The answer is visible. The reasoning is not.

Give Claude 3.5 Haiku the text “Fact: the capital of the state containing Dallas is” and it continues with “Austin”. To get that right, something has to connect Dallas to Texas, and Texas to its capital.

Did the model actually take that step through Texas? Or did it memorise “Dallas … capital … Austin” as one association? Both produce the same word. The difference lives inside the model: dozens of layers, each turning a list of thousands of numbers into another list of thousands of numbers. Looking at those numbers directly tells you almost nothing.

Circuit tracing is a method from Anthropic for turning that arithmetic into a diagram you can read: which concepts became active, and which ones pushed on which. For this prompt, the diagram shows a Texas step in the middle. This page builds up, one piece at a time, how such a diagram is made. The central piece is a component called a transcoder.

2 · Neurons and superposition

Why not just read the neurons?

A neural network already has named parts: its neurons. Each one outputs a number for every word the model processes. If each neuron meant one thing (“Texas”, “is a capital city”), we could read the model like a dashboard.

Most don't. They are polysemantic: one neuron responds to several unrelated things. In Anthropic's 2023 study of a small model, a single neuron responded to academic citations, English dialogue, HTTP requests and Korean text.

The leading explanation is superposition. A model needs to represent far more concepts than it has neurons, so it stores each concept as a direction: a particular mix of many neurons. Those directions overlap. This works because language is sparse: any one sentence uses a tiny fraction of everything the model knows, so overlapping concepts rarely collide.

3 · Approaches

What researchers have tried

Several tools existed before circuit tracing. Each answers part of the question.

Read individual neurons

Find the inputs that make a neuron fire most and describe them.

Breaks on polysemantic neurons

Linear probes

Train a small classifier to detect a concept you suspect is there, such as “this sentence is about Texas”.

Finds only what you already guessed; shows presence, not use

Ablation and patching

Switch off or swap a component and see whether the output changes.

Causal, but coarse, and needs a hypothesis to test

Dictionary learning

Learn, without labels, a large set of directions (“features”) that each mean one thing, and rewrite activations in terms of them.

Discovers concepts unsupervised → SAEs, transcoders
4 · Sparse autoencoders

Rewriting activations as a few clean features

A sparse autoencoder (SAE) is a second, much simpler network trained to undo superposition. It takes a snapshot of the model's activations at one point (a vector of a few thousand numbers) and has two halves:

  • An encoder that turns the vector into activations for a very large number of features (tens of thousands to millions), almost all of them zero.
  • A decoder that gives each feature a fixed direction and rebuilds the original vector as the sum of the active features' directions, each scaled by how strongly it fired.

Training rewards two things that pull against each other: the rebuilt vector should match the original closely, and as few features as possible should be active. That second pressure, sparsity, is what makes features tend to mean one thing each. When researchers look at what makes a single SAE feature fire, it is usually far easier to describe than a neuron.

f = JumpReLU(Wenc x + benc)  // sparse feature activations
x̂ = Wdec f + bdec  // reconstruction of the same x
loss = ‖x − x̂‖² + λ · sparsity(f)

JumpReLU is the activation function used here: a feature outputs zero unless its input clears a learned threshold θ, and then passes it through unchanged. The toy below lets you move that threshold yourself.

What SAEs can't do on their own

An SAE tells you what is present at one point in the model. Circuit tracing needs something more: how one feature caused another. In a transformer, much of that causing happens inside the MLP layers, blocks of ordinary nonlinear neurons that sit between the points where you'd attach SAEs.

Put one SAE before an MLP and one after it and you get readable features on both sides. But the path from one side to the other still runs through the MLP's polysemantic neurons, so any explanation of how input features became output features has to go back through exactly the mess the SAE was meant to avoid.

5 · Transcoders

Replace the MLP instead of describing around it

A transcoder changes one thing in the SAE recipe. Instead of rebuilding its own input, it reads what goes into an MLP and is trained to predict what comes out. Its hidden layer is still wide and sparse, so its features are still readable.

Once it is accurate enough, the transcoder can stand in for the MLP. The MLP's work is then described as: these few features switched on, and each one wrote its own fixed direction into the model. Between one transcoder's output and the next one's input there are no more nonlinear neurons, so the influence of one feature on another becomes a number you can compute.

To see which part is being replaced, it helps to know the three ingredients of a transformer layer:

  • The residual stream: a running vector for each word position that every layer reads from and adds to. Think of it as a shared notepad.
  • Attention: moves information between positions, e.g. from “Dallas” to the last word, where the next word is chosen.
  • The MLP: processes each position on its own. A lot of stored knowledge appears to live here. This is what transcoders replace.
6 · Per-layer vs cross-layer

One dictionary per layer, or one for the whole model

A per-layer transcoder (PLT) gives every MLP its own transcoder: features in transcoder 3 read the stream just before MLP 3 and write only MLP 3's output.

A cross-layer transcoder (CLT), the version the Circuit Tracing paper uses, is a single dictionary for the whole model. Each feature still reads the stream at one layer, but it can write to the output of that layer's MLP and of every MLP after it. Use the layer buttons in the cross-layer view above to see one layer's fan-out.

Why bother? Models often build up the same concept gradually over several MLPs. A per-layer dictionary has to describe that as a chain of near-duplicates: a Texas feature in layer 2 that activates a Texas feature in layer 3 that activates one in layer 4. Each link is real, but none of them is interesting, and the chain makes every path longer. A cross-layer feature writes to all of those layers at once, so the chain collapses into one node.

aℓ = JumpReLU(Wencℓ xℓ)  // features reading the stream at layer ℓ
ŷℓ = Σℓ′ ≤ ℓ Wdecℓ′→ℓ aℓ′  // MLP ℓ output, written by features from every layer up to ℓ
loss = Σℓ ‖ŷℓ − yℓ‖² + λ Σℓ,i tanh(c · ‖Wdec,iℓ‖ · aiℓ)
Reading the equations

xℓ is the residual stream entering MLP ℓ and yℓ is what MLP ℓ actually outputs. The transcoder never sees y while running; it only sees x and must predict y.

The sparsity term charges each active feature in proportion to how much it writes (the norm of all its decoder vectors together), squashed by tanh so that a few strongly active features are not punished much more than a few weakly active ones. The paper reports that JumpReLU with this tanh penalty did modestly better than the alternatives they tried.

Scale: the paper trains CLTs on an 18-layer research model and on Claude 3.5 Haiku, the largest with about 30 million features.

7 · The replacement model

From a stand-in to an exact, linear copy for one prompt

Swap every MLP for its transcoder and you have the replacement model: same attention, same embeddings, but every MLP's work now expressed in features. It's an approximation, and run on its own it doesn't always predict the same next word as the original.

8 · Attribution graphs

Every edge is one exact number

In the local replacement model the only nonlinear choices left are which features fire, and those are fixed by the prompt. Everything between one feature's output and another feature's input is linear: residual stream additions and attention with frozen weights. So the effect of feature s on feature t is simply

As→t = as · ws→t  // s's activation × (s's decoder, carried through frozen attention, · t's encoder)

Computing this for every pair of active features gives the attribution graph. It has four kinds of node:

NodeWhat it isHas inputsHas outputs
EmbeddingA token of the prompt, as it first enters the modelnoyes
FeatureA transcoder feature active at one position and layeryesyes
ErrorWhat the transcoder missed at one position and layernoyes
LogitA candidate next tokenyesno

A full graph has thousands of nodes, so it is pruned to the ones that matter most for the output. The open-source circuit-tracer library by default keeps the nodes that carry 80% of the influence on the output and the edges that carry 98%. Researchers then label features by looking at what makes them fire, and group related ones into “supernodes”. The graphs below are drawn that way.

A graph is a hypothesis, not a proof: it describes the replacement model, which only approximates the real one. The paper checks key claims by intervening on the real model, for example turning down the Texas features and seeing whether “Austin” loses probability. In the companion paper, swapping in California features in place of Texas changed the answer to Sacramento.

9 · Scoring a graph

How much of the answer do the features explain?

Error nodes are honest bookkeeping: they mark where the transcoder fell short. A graph with lots of influence flowing through errors explains less. Two scores summarise this.

  • Replacement score. Start at the output and push influence backwards along every edge, in proportion to edge strength, until it can go no further. It can only stop at nodes with no inputs: token embeddings or error nodes. The replacement score is the share that ends on token embeddings.
  • Completeness score. A gentler, local version: for each node, what fraction of its direct inputs come from non-error nodes, averaged with more weight on nodes that matter more.

One subtlety: a token's embedding stays in the residual stream all the way to the top, so it can push on the output directly, without passing through any feature. That direct path counts towards the replacement score but explains nothing about how the model computed anything. The sliders below let you see how much it can contribute.

The paper uses these scores to compare dictionaries: cross-layer against per-layer transcoders against raw MLP neurons. It also notes they could flag prompts where the method performs poorly. Whether they can do that is the question the project below takes up.

The project this explainer accompanies

When should you not trust an attribution graph?

Jason Soo · pre-registered study of 255 attribution graphs on Gemma-2-2B with per-layer transcoders. The question: can a cheap check, such as the replacement score, tell you in advance whether a graph will be worth hours of human reading? The authors of the method report satisfying insight on roughly a quarter of the prompts they tried.

0.036

Spread of mean replacement score across eight prompt types, from arithmetic (0.709) to induction (0.746).

27 / 27

Matched facts whose replacement score rose when the same question was padded with a longer frame (mean +0.032, about the whole between-category spread).

Highest, yet 0

Induction (copying a token seen earlier) scores highest of all eight types, and every rated induction graph scored 0 for readability: well covered, but circular.

+0.24

Rank correlation between replacement score and human-rated readability (n = 40, p = 0.13). Removing the direct token-to-output paths raises it to +0.30.

The headline is a negative result: no usable pre-flight check for graph quality was found on this model. The induction case shows why. Its explanation, “the token appeared earlier”, is fully covered by features, but the interesting part (how the model knew which earlier token to copy) happens in attention's query-key matching, which the local replacement model freezes.

10 · Limits

What the graphs leave out

  • Attention is frozen, so it is not explained. The graph shows information moving between positions, but not why the model attended where it did. The paper calls its induction case arguably a step back from earlier methods that could at least identify induction heads.
  • Error nodes are unexplained by design. When much influence flows through them, part of the story is missing, and they tend to grow in deeper layers and on unusual text.
  • Only active features appear. If the answer depends on something not firing (a “known entity” feature suppressing an “I don't know” response, say), the graph shows that only indirectly.
  • Graphs are about one prompt. They describe one forward pass. General claims need many graphs and interventions on the real model.
  • Reading them takes human work. Labelling features and grouping them into supernodes is slow; the authors describe a few hours per graph and useful insight on about a quarter of prompts.
11 · Glossary

Terms used on this page

Feature
A direction in a model's activations that corresponds to one recognisable concept, found by dictionary learning.
Polysemantic
Responding to several unrelated concepts. Most neurons are.
Superposition
Storing more concepts than there are neurons by giving each concept an overlapping direction.
Residual stream
The running vector at each token position that every layer reads from and adds to.
MLP
The per-position block of neurons in each transformer layer; the part a transcoder replaces.
SAE
Sparse autoencoder: rebuilds activations at one point from a few active features.
Transcoder
Like an SAE, but reads an MLP's input and predicts its output, so it can replace the MLP.
PLT / CLT
Per-layer transcoder (one per MLP) / cross-layer transcoder (one dictionary whose features write to all later MLPs).
JumpReLU
Activation that outputs zero below a learned threshold and passes the input through above it.
Error node
The difference between the real MLP output and the transcoder's prediction, at one layer and position.
Local replacement model
The replacement model plus error nodes, with attention and normalisation frozen, for one prompt. Its output matches the original exactly.
Attribution graph
The network of nodes and exact linear effects in the local replacement model, pruned to what matters for the output.
Supernode
A hand-made group of related features drawn as one node.
Replacement score
Share of the output's influence that traces back to token embeddings rather than error nodes.
